# 商品数据分析

## 目标

把商品数据变成清晰的商品决策：哪些值得继续放量、哪些适合承担利润、哪些要先修问题、哪些继续观察。每个商品都要有一句老板能看懂的判断和一个下一步动作。

## 项目边界

- 只读取当前项目根目录及 `data/`、`docs/`、`output/`、`feishu/` 中的文件。
- 先读取项目根目录的 `AGENT.md`，再处理数据。
- 不访问项目外文件。用户给出项目外数据时，请其先放入 `data/`。
- 默认只生成本地商品分析，不直接修改真实飞书资源。

## 输入选择

1. 优先使用用户指定的 CSV、日期、商品、商品 ID、SKU 或渠道。
2. 未指定日期时使用数据中的最新日期。
3. 用户只说“今天”时，优先查找 `data/daily_metrics_YYYY-MM-DD.csv`。
4. 模板文件只用于模拟测试，不冒充真实店铺结果。
5. 结合 `docs/business_context.md` 判断活动让利、新品测试、库存策略和竞品变化。

重点字段：

`product_name, product_id, sku, gmv, orders, cost, profit, profit_margin, refund_rate, roi, inventory, material_ctr, live_conversion_rate`

如果同一商品存在多个 SKU 或渠道，保留维度差异；只有在口径明确时才汇总，避免把渠道问题错误归因到商品本身。

## 隐私处理

商品分析不需要客户姓名、手机号、地址、订单号或账号 ID。检测到此类字段时先脱敏，并在结果中只保留商品和经营指标。

## 执行流程

1. 确认输入文件、日期和分析范围。
2. 检查商品标识、金额、比例字段和重复数据。
3. 在项目根目录运行：

```powershell
python workflow.py product-analysis --input data/daily_metrics_YYYY-MM-DD.csv --date YYYY-MM-DD
```

4. 读取 `output/product_analysis_YYYY-MM-DD.md`。
5. 如用户指定商品或 SKU，在最终回复中只突出相关商品，同时保留必要的全店参照。
6. 检查每个重点商品是否包含分层、数据依据、经营判断和下一步动作。

## 商品判断框架

依次检查：

1. 销售贡献：GMV、订单量和全店贡献度。
2. 赚钱质量：利润、利润率和成本结构。
3. 售后风险：退款率及其历史变化。
4. 投放效率：ROI，特别关注高 GMV 低 ROI。
5. 库存压力：当前库存能否支持继续放量。
6. 承接能力：素材点击率和直播成交转化是否匹配。

使用当前工作流的分层口径：

- 主推款：销售贡献较高，利润率不低于 30%，ROI 通常不低于 2，具备继续放量基础。
- 利润款：利润率通常不低于 40%，ROI 不低于 1.5，适合承担利润或搭配销售。
- 风险款：利润率低于 30% 或退款率达到 10%，先处理成本、售价、产品和售后问题。
- 观察款：有销售或利润信号，但转化、库存或稳定性仍需观察 1-3 天。
- 淘汰候选：赚钱能力和投放回收都弱，暂停扩大投入并验证是否还有稳定成交价值。

## 风险规则

- 利润率低于 30%：明确标记风险，并写成“能卖，但赚钱能力弱”。
- 退款率异常升高：提醒检查产品质量、尺码/规格、物流时效和客服话术。
- 高 GMV 低 ROI：提醒确认是否靠投放硬拉销量。
- 高销量低库存：提醒补货、断货和投放节奏风险。
- 高点击低转化：检查详情页、价格、信任感、直播讲解和人群匹配。
- 缺少历史数据：不强行判断趋势，只描述当前水平和需要补充的数据。

## 固定输出结构

```markdown
# 商品数据分析 - YYYY-MM-DD

## 经营结论
## 商品分层
## 商品明细
## 风险提醒
```

商品明细至少包含：商品、分层、GMV、订单、利润率、退款率、ROI、库存和经营判断。

最终回复再补充一个简短的“下一步动作”摘要：

- 主推款：继续放量，同时盯库存和退款。
- 利润款：增加承接场景或搭配销售。
- 风险款：先处理利润、退款或投放问题，再决定是否加投。
- 观察款：限定测试预算，观察 1-3 天。
- 淘汰候选：暂停扩大投入。

## 表达要求

- 不只说“指标高/低”，要说明对经营意味着什么。
- 不因为 GMV 高就自动推荐放量，要同时检查利润、退款、ROI 和库存。
- 每个重点商品只给一个最优先动作，避免堆砌建议。
- 使用老板能快速理解的经营语言，避免财务黑话。

## 完成标准

- 分析范围和日期清楚。
- 商品分层有数据依据，不只按销售额排序。
- 所有利润率低于 30% 的商品被标为风险。
- 退款异常提醒包含产品、尺码/规格、物流和客服话术排查。
- 每个重点商品都有一句判断和一个下一步动作。
- 客户敏感信息已脱敏。
- 输出只写入 `output/` 或经确认的飞书目标。
