# 可视化选品工作流

把“研究事实 → 结构化数据 → 决策结论 → 可视化交付”做成一条可复用流水线。默认交付三类资产：飞书多维表格、飞书分析文档、飞书妙搭 HTML 看板；用户只要求其中一部分时，执行对应阶段并保持字段和口径兼容。

## 0. 先锁定范围与口径

开始前只补问会改变结果的缺失信息：品类、目标市场/平台、活动节点、目标人群、预算或目标价格带、期望覆盖数量、是否需要直接发布。没有特别说明时采用以下默认值：

- 覆盖至少 20 个可比产品，按品牌、价位和产品定位分层，不用 20 个相似型号凑数。
- 所有价格字段区分“公开/原价”和“活动/券后到手价”；618、双11等活动价必须标注活动口径和采集日期。
- 研究结论以可追溯证据为基础；没有评论量或统计样本时，把“高频痛点”写成定性优先级，不伪造百分比和评论数量。
- 研究数据、文档和网页都带调研日期、批次和证据等级，方便后续追加而不是覆盖历史结果。

若用户只说“做选品调研”，先用上下文推断品类和场景；仍无法确定时只问 1–3 个关键问题，不要直接开始大范围抓取。

## 1. 搜集市场与竞品数据

需要联网核验时使用 web；需要写入飞书时使用 `lark-base`；不要把搜索摘要直接当作事实。每个产品至少记录：

| 字段 | 记录要求 |
|---|---|
| 产品名称、品牌、型号 | 用官方/商品页名称，统一品牌和型号写法 |
| 公开价格下限/上限 | 记录常规公开价或官方标价，无法确认时留空并说明 |
| 活动参考价 | 记录活动规则、券前/券后状态和采集日期 |
| 价格带 | 统一为可筛选区间，如 500–1000 元，不把价格带当精确成交价 |
| 核心卖点 | 用 1–3 个可验证功能或体验表达 |
| 差评痛点 | 优先来自评论、实测、售后反馈；区分事实和推测 |
| 适合人群 | 身高/体重/使用时长/场景/预算等可行动标签 |
| 关键参数/功能 | 只记录会影响购买决策的参数，不堆规格表 |
| 选品评分、618建议 | 评分维度和建议必须在结果中解释 |
| 证据等级、来源链接、调研日期 | 每行必须可追溯；来源不足时降低证据等级 |

研究时优先组合：官方商品页/旗舰店、平台榜单与活动页、第三方实测、用户评论或售后讨论。跨平台价格不直接横比，先写清平台、版本、赠品、安装和优惠条件。

### 研究质量门槛

1. 覆盖数量达到用户要求；如果不足，明确“已覆盖/待补充”，不虚构产品。
2. 价位分布覆盖主流成交带、升级带和价格锚点，避免样本只集中在一个品牌。
3. 至少做一次痛点归类：适配、舒适度、耐久、安装/售后、价格/促销等。
4. 结论只引用表内事实；从样本推断市场趋势时标注“基于本次样本的观察”。

## 2. 创建飞书多维表格

使用 `lark-base` skill 建立或更新 Base。默认建两张表：

1. `产品调研`：一行一个产品，承载原始研究事实。
2. `618选品结论`（活动名称按用户场景替换）：一行一个选品方向，承载策略结论和行动。

`产品调研` 的字段名与类型、视图和 `618选品结论` 的策略字段见 [references/base-schema.md](references/base-schema.md)。先建字段，再批量写入记录，最后创建视图和筛选；不要把长段报告直接塞进单元格。

推荐视图：

- `全量调研`：按调研日期倒序，保留全部产品。
- `价格带全景`：按活动参考价或价格带分组。
- `618重点候选`：筛选“重点关注/首发建议”和高评分。
- `风险与差评`：展示差评痛点、证据等级和来源。
- `策略总览`：展示方向、到手价、优先级、主打配置、风险和下一步。

写入后检查：记录数、必填字段、价格上下限关系、重复产品、来源链接可用性和筛选结果。返回 Base 链接与数据覆盖摘要。

## 3. 根据表格生成可读分析文档

使用 `lark-doc` 基于多维表格生成文档；详细版式见 [references/visual-doc.md](references/visual-doc.md)。文档的目标是帮助运营做决策，不是把每行调研复制成论文。

推荐结构：

1. 标题、调研范围、数据批次和价格口径。
2. **核心结论**：3–5 条，优先用颜色区块/高亮块表达；每条包含结论、证据、动作。
3. **市场观察**：用价格带表格、趋势卡、竞品分层，不写连续长段。
4. **竞品对比**：只展示影响决策的字段，完整字段留在 Base。
5. **用户痛点 Top5**：排名、痛点、影响场景、证据等级、产品应对动作。
6. **推荐选品方向**：通常 3 套，明确零售价、活动到手价、目标人群、主打配置、传播话术、竞品参考、风险和优先级。
7. **风险与决策门槛**：风险—原因—验证动作—放量门槛。
8. **下一步计划**：按周或阶段列负责人、产出物和指标。

排版原则：

- 能表格化就不写长段；能用 3–5 个要点就不写一大段。
- 关键数字加粗；结论用绿色/黄色/红色区块区分“推荐/验证/暂缓或风险”。
- 每个区块只讲一个问题；标题、结论、证据、动作分层，避免标题和正文挤在一起。
- 复杂策略用矩阵、时间线、分栏或小卡片；不要用装饰性图形替代数据。
- 不把“高频”写成虚构频次；若无严格统计，标注“定性优先级”。

完成后读取或检查文档，确保标题层级、表格、重点高亮和链接都能正常显示，并返回文档链接。

## 4. 生成并发布 HTML 网页看板

使用 `lark-apps` 的 creative HTML 工作流，不使用旧版 `+html-publish`。网页面向电商运营快速扫读，默认包含：

- 核心结论与一线经营策略
- 市场观察与竞品价格带图表
- 用户痛点 Top5
- 三套选品方向和推荐优先级
- 风险提示与下一步计划

视觉规则：

- 使用运营看板风格：强对比色、清晰网格、数字、标签、表格、进度条和 ECharts 图表。
- 不做论文式长文；每张卡片控制为一句主张 + 关键指标 + 下一步动作。
- 价格图表统一活动到手价口径，图下注明样本数、采集日期和价格说明。
- 颜色有语义：绿色=推荐/可放量，黄色=验证/观察，红色=风险/暂缓，深色=经营结论。
- 保证桌面端和窄屏可读；检查中文标题换行、行高、卡片高度和图表标签，避免文本重叠或大面积空白。

发布流程：

1. 先用 `lark-cli apps +list --keyword` 定位是否已有目标应用；已有应用直接修改，不重复创建。
2. 新应用用 `apps +create --app-type html --as user`，然后 `apps +init` 到独立目录。
3. 写入 HTML 后运行基础检查，`git diff --check`，提交并推送 `sprint/default`。
4. 用 `apps +release-create` 发布，轮询 `apps +release-get`，只有 `status=finished` 且返回 `online_url` 时才把链接交给用户。
5. 若仓库有远端新提交，先刷新 Git 凭证、fetch/rebase，保留远端改动后再推送；不要强制覆盖远端分支。

## 5. 交付与复盘

最终交付用短摘要说明：覆盖多少产品、价格带分布、推荐方向和主要风险，并给出：

- 飞书多维表格链接
- 飞书分析文档链接
- 妙搭 HTML 看板链接

如果某个资产因权限、登录、缺少数据或发布失败未完成，明确指出阻塞点和已完成部分，不编造链接。后续更新优先追加新的调研批次，保留历史价格和结论，并在文档/看板中注明更新时间。
