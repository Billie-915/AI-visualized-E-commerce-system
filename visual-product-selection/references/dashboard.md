# 妙搭 HTML 看板规范

## 结构

推荐采用单页运营看板：

1. 顶部：项目名、活动节点、更新时间、数据口径。
2. Hero：一句话经营结论 + 两个首发价带。
3. KPI：竞品数、推荐方向数、痛点数、首发 SKU 数。
4. 价格带：ECharts 横向柱状图或分布图。
5. 痛点 Top5：排名条形图/条目卡。
6. 三套方向：统一字段的三列卡片。
7. 推荐优先级：P0/P1/P2 矩阵或攻打顺序。
8. 风险提示：风险、影响、上线前动作表。
9. 下一步：按周时间线。

## 视觉与数据规则

- 页面应像电商运营作战板，不像学术报告；短句、数字和动作优先。
- 推荐颜色：深海军蓝、荧光绿、珊瑚红、浅蓝、暖黄；颜色必须承担状态含义。
- 避免渐变、玻璃拟态、过多圆角和阴影；使用边框、色块、网格制造层次。
- 图表显示样本数、单位、价格口径和采集日期；没有统计数据就展示定性优先级，不伪造精确频次。
- CSS 必须显式设置中文标题的 `line-height`、最大宽度和响应式断点，检查标题换行、卡片高度和空白比例。
- 外部依赖优先使用飞书 CDN；ECharts 使用 `echarts@5.6.0`。

## 发布检查

使用 `lark-apps` 参考中的 HTML 应用流程：创建或定位 app → 初始化代码仓库 → 写入 HTML → `git diff --check` → commit/push → `+release-create` → `+release-get` 直到 `finished`。只有 `online_url` 来自本次 finished release 时才能交付。
